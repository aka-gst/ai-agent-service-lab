## Вывод

Цепочка «проверяемый расчёт → RAG → локальная модель → валидация источников» работает на демонстрационном сценарии. Данные отчёта не отправляются во внешний облачный API.

## Сценарий возвратов

Вопрос «У какого товара больше всего возвратов и что стоит проверить?» также проверен через Docker и Ollama. Помощник рассчитал:

- кроссовки: 20% — 5 возвратов из 25 выкупленных;
- футболка: 10% — 8 из 80;
- общий уровень: 12,38% — 13 из 105.

Модель правильно выделила кроссовки, перечислила необходимые для диагностики данные и не назвала предполагаемую причину доказанным фактом.

## Сравнение периодов

Проверен сценарий с двумя CSV. Для тестовых данных система определила:

- кроссовки: снижение выкупа с 80% до 50%, то есть −30 п.п.;
- футболка: снижение с 80% до 70%, то есть −10 п.п.;
- самое сильное падение произошло у кроссовок.

Сравнение выполняется проверяемым Python-кодом. Затем Ollama объясняет результат по RAG-справочнику. В живой проверке модель сохранила направление и величину изменений, не назвала гипотезы установленными причинами и сослалась на раздел `metrics-guide.md#Сравнение периодов`.
